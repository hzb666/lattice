# Chemex Agent Guide

## 项目方向

- 使用 Rust 构建面向化学研究的论文编辑器，Windows 优先。
- ChemDraw 负责化学绘图与编辑，LaTeX 负责最终论文排版；GPUI 承载桌面交互。
- Chemex 是 Lattice 的化学文档领域模块；界面和论文构建复用 Lattice。
- 分阶段交付：先验证绘图进入论文的闭环，再扩展结构识别和编号，保留完整编辑器的架构边界。

## 工作方式

- 修改前阅读相关实现、调用方、测试与项目文档，先明确影响范围。
- 采用满足需求的最小完整改动，复用已有代码和标准库，避免无关重构。
- 保留用户未提交的改动；未经明确要求，不提交、推送或改写 Git 历史。
- 发现新证据时修正判断；区分设计建议、文档能力和本机实测结果。

## 架构与边界

- 按职责组织模块；出现实际复用、依赖隔离或独立验证需求时再拆 crate。
- 保持依赖单向、无环；核心解析和构建逻辑不依赖 GPUI 或界面状态。
- 界面负责交互和展示，业务流程集中在核心模块，避免在事件回调中重复实现。
- 隔离 ChemDraw、操作系统和 LaTeX 工具调用，避免平台细节扩散到业务代码。
- 沿用底座已有的编辑、项目、保存、构建和预览能力，避免重复实现同一职责。
- 复用上游时记录来源与版本，保留许可证，集中维护定制差异，避免无关改名和重组。
- 绘图导出与化学语义解析独立运行；结构识别失败不得阻断原图导出和论文编译。
- 不预建空模块、通用框架或插件系统；具体目录和依赖随实际代码演进。

## Rust 代码规范

- 优先清晰的函数、结构体和枚举；仅在真实边界需要时引入 trait 和泛型抽象。
- 借用优先，所有权转移显式；避免为绕过借用检查而复制大对象。
- 路径使用 `Path` / `PathBuf`，不假设文件名是 UTF-8。
- 可恢复失败返回 `Result`，使用 `?` 传播并保留错误原因与操作上下文。
- 核心库使用可供调用方判断的错误类型；应用入口可统一补充错误上下文。
- 不用 `unwrap`、`expect` 或 `panic!` 处理文件、解析和外部工具的正常失败。
- 缩小 `unsafe` 与 FFI 范围，记录安全前提；优先使用经过验证的绑定。
- 保持函数职责单一、嵌套浅、命名明确；注释解释原因和外部约束。
- 依赖按需引入，统一管理兼容版本，提交应用的 `Cargo.lock`。

## 文件与外部工具

- 原始 CDXML/CDX 是权威源文件；自动转换和编号替换只操作生成副本。
- 保留未知对象与属性，不用部分解析模型重新序列化并覆盖整份原始绘图。
- 最终图形通过 ChemDraw 导出，不从分子图、SMILES 或 RDKit 重建原始 Scheme。
- 文件事件只作为变化提示；读取前确认写入稳定，处理连续保存和文件替换。
- 生成结果先写入临时位置，校验成功后发布；失败时保留上一次成功产物。
- 外部命令使用程序与参数分别传递，不把路径或输入拼接到 shell 命令中。
- 保留退出状态、标准错误和必要日志；不静默吞掉会影响结果的失败。
- ChemDraw 自动化接口、导出格式和 ObjectTag 保留行为必须按实际版本验证。

## 并发与状态

- 解析、导出、转换和编译不得阻塞 UI 主线程。
- COM 对象留在所属 apartment；使用 STA 时维护消息循环，不直接跨线程传递接口。
- 明确后台任务的生命周期与结果归属，避免旧任务覆盖较新的成功结果。
- 优先简单任务队列和消息传递，不默认增加异步运行时或全局共享可变状态。
- 不关闭、覆盖或终止用户已有的文档与进程。

## 测试与交付

- 对非平凡逻辑补充定向测试，覆盖关键行为、边界和失败路径。
- 解析测试保留真实 ChemDraw 样本；测试副本与原始样本分开，注明来源。
- 分开验证语义解析、原文件完整性、矢量导出与视觉保真；不能相互代替。
- 建立 Cargo 工程后，按改动运行格式检查、Clippy 和相关测试：
  `cargo fmt --all -- --check`、
  `cargo clippy --workspace --all-targets --locked -- -D warnings`、
  `cargo test --workspace --locked`。
- 如实报告已运行命令和结果；未执行或受阻的验证明确说明，不声称通过。
- 文档就地维护，保持简洁；详细设计和进度放入对应文档，本文件只保留稳定原则。

工程边界见 `docs/DEVELOPMENT.md`，当前进度与验证记录见 `docs/ROADMAP.md`。
